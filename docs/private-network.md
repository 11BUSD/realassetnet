# Private research connector

The private connector provides an operator-only read view of a separately maintained institutional research database. It does not copy counterparties into public fixtures, update research records, send messages, assert a partnership or execute financing. Its configuration is disabled by default.

Configure locally with `python scripts/configure_private_network.py --database <absolute-external-database-path>`. The source must already exist outside the entire public application project, including its runtime directory. The script validates the expected research tables and writes the resolved source location plus an operator-key digest into excluded `runtime/private-network.json`. A randomly generated key is stored separately in excluded `runtime/operator.key`; the command does not print it. Existing configuration or keys are not overwritten. Manage rotation explicitly while the connector is disabled.

`GET /api/network/status` requires an authenticated application admin and returns only configured/key-required/read-only status. `GET /api/network` requires both that admin session and the matching `X-Operator-Key` request header. A seeded demo reviewer alone cannot obtain private research. The header is an additional local operator control, not a production identity, hardware key or network security boundary. Keep the key out of browser persistent storage, screenshots, logs, Git and public exports. Files use restrictive creation modes where supported; review inherited Windows filesystem ACLs on the runtime directory.

The returned snapshot contains organization summaries, roles, explainable score factors, source URLs, documented relationships and a prioritized preparation queue. Organization records older than 90 days are marked stale. READY requires currently verified professional and contact evidence no older than 30 days, currently verified organization evidence no older than 90 days, a matching sourced contact channel and nonfuture verification dates. Invalid or missing dates downgrade to RESEARCH, and the verified-contact value is withheld. Contacted, active-relationship, not-now and do-not-contact states suppress the daily queue. Future or invalid not-before dates also suppress it. A latest recorded blocked interaction is respected. One record per canonical network group is selected, up to 50 rows.

The source is opened with SQLite URI `mode=ro`, `query_only`, disabled trusted schema and an authorizer that denies mutation or database attachment. Queries are fixed by the adapter; no arbitrary SQL or private parent-module code is loaded. Each response uses a read transaction. Public-project source paths are rejected after resolving links. The application audit records that an operator read occurred and the organization count; it does not copy source records, contact values, operator credentials or the private file path.

The response mode is `PRIVATE_READ_ONLY`. Summary keys are `organizations`, `sources`, `people`, `mandates`, `documented_relationships` and `queue`. Organization objects add `roles`, `score_breakdown`, `network_factors` and `current_verification`. Queue rows preserve `stored_status`, compute current `status`, expose verification/source dates, and always set `outreach_enabled=false`. Documented external relationships remain historical claims; permission to introduce is not inferred. Research freshness is not consent, deliverability, sanctions clearance, legal qualification or available capital.

The current adapter supports the versioned research schema that preceded the application. It does not implement transaction mandate matching, writeback, multi-operator entitlements, production encryption/key management or a CRM workflow. Schema mismatches fail closed with generic errors. Tests use an isolated synthetic research database and do not touch real configuration or research data.
